# ai/doc/ ディレクトリ運用ガイド

このディレクトリは、プロジェクトの**全文脈情報**を集約する場所です。
Backlog などの外部チケット管理は使わず、すべてここに残します。

エンジニア引き継ぎ時、ここを読めば全部分かる状態を保つのが目標です。

---

## ファイル構成

| ファイル | 役割 | いつ更新するか |
|---|---|---|
| `01-context.md` | プロジェクトの目的・課題・背景・成功条件 | `/setup` 実行時に初期化。前提が変わったら更新 |
| `02-requirements.md` | 機能要件・要求の一覧と対応状況 | 新しい依頼を受けたら追記。完了したら対応状況を更新 |
| `03-decisions.md` | 重要な意思決定のログ（ADR形式） | 設計判断をしたら追記 |
| `04-architecture.md` | 現在の技術アーキテクチャ | アーキテクチャに影響する変更で更新 |

---

## 書き方の原則

### 嘘を書かない
- 動かないコードを「動いた」と書かない
- 推測を断定で書かない（「未確定」と明記）

### 古い情報を消さない
- 削除ではなく**更新履歴**を残す
- 過去の判断が辿れる状態を保つ
- 大きく変わった場合は `<details>` で畳んで残す

### 1コミット = 1ドキュメント追記
- 実装コミットには対応する doc 更新を含める
- ドキュメントを書かないコミットは `chore:` プレフィックスのみ許可

## 引き継ぎ時のチェックリスト

エンジニアに渡す前に以下を確認:

- [ ] `01-context.md` の課題・背景・成功条件が書かれている
- [ ] `02-requirements.md` の対応状況が最新
- [ ] `03-decisions.md` に主要な意思決定が記載されている
- [ ] `04-architecture.md` が現在の構成と一致している
- [ ] ステージング URL が `01-context.md` 末尾に記載されている
- [ ] 残課題が `02-requirements.md` の「未着手」として明示されている

---

## なぜ Backlog を使わないのか

`ai/doc/03-decisions.md` の「Backlogを採用しない」決定を参照してください。
要約: 外部依存を減らしてシンプルさを優先。Git 履歴とこの `ai/doc/` で十分な文脈を残せる。
